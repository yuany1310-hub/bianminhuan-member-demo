便民欢｜两级分销推广功能开发评估说明
商城最终总方案新增评估项 · 2026年11月2日整合

一、本次已对齐的场景
本功能已纳入商城最终总方案需求评审。新增范围的开发费用、工期及物流付款服务费仍须单独确认，不默认包含在原1.8万元、15天报价中。此版按用户后续明确的两级关系展示；5%和其他金额、天数、门槛仅为方便评估的模拟值，正式规则可由后台配置。

一级A自己推广成交：演示本人按商品有效实付5%计佣。此直接成交比例为样板示例，用户未单独确定正式数值。
二级B已绑定A，B推广成交：同一订单B直接佣金5%＋A上级佣金5%，两人各得一份。基数均为商品有效实付，不采用利润，不要求接入真实进货成本。
独立二级C没有上级，C推广成交：演示仅C本人5%，不生造上级，不把另一份自动发给其他推广人。
普通消费者D：可开启模拟“净完成消费达标成为二级”，示例门槛1000元；默认关闭，可在样板操作开启。D只绑定一名一级，不形成三级。

网页只有虚构商品、订单、关系及本机状态。分享、付款、物流、自动升级、结佣和银行卡打款均未接入真实生产系统，不能把演示成功视作实际开通。

二、推广身份与关系
1. 后台审核、开通、停用推广人，设可推广门店、商品范围和有效时间。一级、二级是推广身份，独立于商城消费会员等级。
2. 一级没有上级；二级最多绑定一名一级，也可不绑定。禁止自己绑定自己、循环关系、一级挂在别人之下、二级挂二级及第三层关系。
3. 绑定记录保存双方稳定编号、生效/失效时间、管理员及原因。管理员改绑只影响后续新支付订单，老单保留支付时关系快照，不追溯挪佣金。
4. 每单锁定一个直接推广人；该人若为绑定一级的二级，额外锁定一个一级受益人。一级自己直接成交只生本人直接佣金，独立二级只生本人直接佣金。
5. 停用或资格异常后暂停新推广；历史已支付订单及退款仍按原快照处理，不因改身份抹掉旧账。

三、商品、系列、标签怎样设比例
总部维护商品源、系列和标签；门店SKU独立配置上下架、售价、库存和是否参与分佣。可继承总部默认，门店覆盖规则需最终确认。样板先展示一家门店，不表示POS或多门店同步已经完成。
1. 后台对指定门店的单个商品/规格、系列、标签分别设置“直接佣金比例”和“一级上级佣金比例”，可配有效时间和启停。示例5%＋5%不是正式政策；必须同时显示每单总佣金成本。
2. 暂定命中顺序：单商品/规格 > 系列 > 标签 > 默认；最终只采用一种匹配规则，不叠加。同层多条按后台优先级，数字小优先；同层、同优先级、范围重叠的启用规则阻止生效。
3. 商品参与分佣开关为总闸，新商品默认关闭。未开启时即使命中标签/系列也不计新佣金；关闭分佣仍可正常销售。单品排除优先于其他规则。两个比例字段均允许0%，0%有效且不得回退；没有有效规则不计佣。
4. 保存须校验空值、负值、非数字、越界比例、最多两位小数及两份合计比例。后台需有毛利/佣金预算审批，不能把“实付作为基数”解释为不管成本。
5. 后加商品、标签及规则改动只影响新订单。支付时保存商品名称规格、价格、系列标签、参与开关、两份比例、规则版本、适用范围及上级关系快照；停佣、改价或软删除不改旧单的结佣、退款和对账。

四、分享归因与计佣基数
1. 推广人分享商品、系列或标签入口，带服务端可验证的推广标识。客户正常在商城下单，商城收款和门店/快递履约。真实分享卡片、路径、小程序码与跨入口归因由开发验证。
2. 归因窗口示例7天，暂按有效期内最后有效入口确定直接推广人，支付时锁定当前订单；新老客均可，自购默认排除。窗口、重购、自购和多个链接处理仍属正式政策待定项，不默认永久绑定客户。
3. 基数为商品行有效实付，优惠券与折扣先分摊，不含运费、充值交易或赠金支付。商城钱包本金用于真实购货的计佣范围由正式规则确认，充值本身不计佣。退款后按原单商品行累计净实付重算。
4. 金额以整数分、比例用可精确计算的单位保存；每位受益人逐商品行向下取整到分后汇总。每份分录关联订单行、直接/上级类型、受益人、规则和关系快照及原始业务事件。
5. 支付回调、履约任务、退款通知和结佣重复执行只处理一次；订单行＋受益人＋分录类型＋业务事件有稳定唯一约束，不能改请求号就多发。两个人的结佣分录应在同一可靠业务处理单元完成，失败重试不能半边漏发或重复发。

五、消费达标成为二级的独立演示
1. 默认开关关闭；可操作开启、输入模拟门槛并查看D的净完成消费进度。示例1000元，可用于演示达到和未达到两种情况，不表示正式购买入门条件。
2. 门槛示例按已完成履约的有效商品净消费，不把充值、运费、赠金或退款算有效消费；订单重复回调不重复累计。
3. 达标后只生成二级身份，绑定已核验的来源一级；样板可用一级A作为明确来源。来源缺失、冲突或来源为二级但其上级未核验时，应提示待人工确认，不默认造关系或升成三级。正式来源优先级、周期、授权及准入流程仍需确定。
4. 达标后发生退款、导致资格条件不满足，演示先冻结其新推广资格并提示人工核对。是否撤销、补足后恢复、按何时点判断为正式待定策略；不追溯更换老单归属或直接删除老佣金。

六、快递签收、售后和两人最终结佣
1. 支付、待发货、已发货、运输途中只锁定A/B各自预估佣金，不向任何一人分钱，不进入可提现余额。
2. 快递订单记录公司、单号、包裹/商品行对应、轨迹、最新状态、原始签收时间、当前有效签收与确认收货时间。默认样板一单一包裹，全为DEMO虚构单号和轨迹。
3. 默认物流签收＋商城确认收货 → 进入佣金观察期（示例7天）→ 观察期结束且无未处理售后 → 校验后一次性给本单各受益人结佣。未签收、仅发货、仅填单号均不能越过门槛。主动/自动确认政策另定；重复通知不重置原确认时间或观察期。
4. 自提另走提货码核销后进入观察期，不要求快递单号，不重复收款、扣库存或结佣。
5. 拒收、退回中、配送异常和售后处理中暂停结算；物流退回不等于退款成功或商品验收回库。异常恢复须核对，旧批次或乱序回调不能覆盖有效状态、提前或重复结佣。多包裹以后按全部应履约包裹完成汇总，不以一个包裹签收结整单。
6. 真实物流查询/订阅的供应商、权限、签名、回调验证、重试、漏事件补查、脱敏及费用单独评估；不在公开样板采集真实收件资料。

七、退款怎样同时影响两个人
1. B有效实付100元、直接/上级各5%：预估B5元、A5元，总10元。退20元后净实付80元，B保留4元、A保留4元，总8元；全额退款两份均归零。5%为模拟比例。
2. 结算前减少各自待结算佣金；结算后分别从各自可提现余额冲回。必须同时处理原单所有受益人，不漏A，也不按后来改绑的新上级扣款。
3. 按原比例、关系和累计退款重算，每份只扣差额；同一退款通知不重复扣，累计冲回不超原佣金。
4. 任一受益人已提现或余额不足，差额记在该人待抵扣并暂停该人的后续提现，后续佣金先抵扣。不拿另一个人的账户补差，不从买家的商城钱包或收银余额扣款。
5. 提现处理中发生退款，先暂停相关付款并核对。付款结果未知时先查结果，不能一边释放冻结金额一边继续打款。

八、可提现余额与银行卡提现分开
1. 达到最终条件后自动结佣进入各人独立推广佣金账户的可提现余额，名称是“结佣入账”，不是银行卡自动到账。
2. 推广佣金与商城购物钱包、本金、赠金、积分及POS资产分开。A、B、C各看自己的待结算、可提现、申请冻结、累计已付款和待抵扣。
3. 提现申请校验门槛、余额、已获推广身份、资金冻结状态及待抵扣；新推广资格暂冻不自动锁住无资金债务的旧有效佣金。提交后立即冻结，避免多申请重复使用。流程为申请中 → 审核通过待付款 → 已打款；也可驳回或确认付款失败。
4. 同一申请驳回/失败仅释放一次，释放额先抵扣该人应冲回金额。审核通过不等于到账，实际付款结果须有可靠流水；重复通知不重复计已付款。
5. 银行卡或其他实际付款通道、商户能力、收款身份、手续费和财务要求另核。样板只模拟，不代表真实自动打款已经开通；一级不能代二级申请或批准提现。

九、权限、后台和验收
一级只看直属二级名单、绑定状态及本人应得佣金汇总；不能查看下级买家的姓名、电话、地址、订单客户名单、下级钱包或付款账户、商家成本及利润明细。二级只看自己的必要脱敏订单、履约和佣金记录，不默认获得完整客户联系方式。
正式系统须服务端鉴权、数据归属校验、日志与导出限制，不能只靠页面隐藏。管理员关系配置、运营比例审批、财务提现付款按权限分开。示例角色切换不等于生产权限已实现。

后台最小模块：商品源及门店SKU、标签增减、上下架软删恢复、参与分佣开关与双比例、两级身份及绑定、独立二级、消费门槛演示/资格异常、订单商品关系规则快照、逐人佣金退款、物流售后门槛、逐人提现对账、日志和权限。

重点验收：A直接成交、B带A两份、独立C一份；无循环/三级；0%不回退、规则冲突拦截；改比例/改绑不动老单；支付发货途中双方均0可提现；最终条件满足双方各一次入账；部分退款5+5变4+4且重复不变；一人提现后退款只形成该人债务；达标演示可开关和改门槛、未达标不升级、退款资格异常冻结新推广；上级界面及接口不泄露下级买家与成本信息。

十、正式立项前确认
确认参与人群和门店商品、两份正式比例和预算、归因窗口及自购重购、消费资格门槛与授权/来源/退款策略、签收与确认收货及观察期、提现通道门槛和费用、现有模块复用/新增范围、各自报价工期与验收人。

消费达标取得推广资格、上级按下级业绩计佣，需要法务和微信平台按实际方案核验；不能仅凭“只有两级”判断合规。参考国家市场监督管理总局公布《禁止传销条例》第二条、第七条：

十一、手机端分享和购买交付
1. 手机为主要体验：推广人选品分享、客户购买、我的佣金和订单履约四类入口，大按钮、可读字号和无整页横向溢出。电脑版可预览手机画面；手机直接打开完整可用界面。
2. 推广人看到可推广商品、规格价格、本人预估佣金及分享卡。消费者只看到商品、门店、规格、收货方式、购买及售后信息，不展示上级收益和运营后台配置。
3. 分享、打开商品、下单、快递/自提、观察结佣与提现共用一套订单及账本状态，不能各画一套不互通的演示。
4. 真实微信分享卡片、小程序码、归因及付款仍需开发按主体与账号能力核验；浏览器复制演示路径不表示已实现小程序分享。

十二、商品增减和旧分享链接
1. 新增商品填写名称、规格、单位、价格、系列和标签，参与分佣默认关闭。只有同时满足上架可售、参与开关和有效规则，才可进行新推广计佣。
2. 可为商品加入或移除标签，也可新增标签；标签有稳定编号，名字不可空或重复，多个标签只作匹配范围，不自动授权分佣。配置导致同优先级规则重叠时应阻止保存或生效。
3. 关闭分佣：商品可继续正常购买，旧推广链接不再为新订单计佣。下架或软删除：旧链接提示不可购买，付款前必须重新校验，不能绕过。
4. 已支付订单沿用商品和规则快照：即使后来改标签、停佣、下架或软删，仍能展示原商品、完成履约、结佣、退款及对账。有关联订单的商品不得物理删除。
5. 改价时支付前重校验并提示重新确认；不静默按不同于页面展示的价格收款。恢复商品需重新校验上架、参与开关和规则，不重复发旧佣金。
6. 至少验证新增默认停佣、标签增减命中、冲突拦截、停佣仍可买不计新佣、下架软删旧链接不可买、旧单快照稳定以及恢复后的规则。
