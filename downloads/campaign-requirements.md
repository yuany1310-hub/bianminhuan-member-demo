# 便民欢商城｜拼团、秒杀、上新开发补充需求

版本：2026年10月27日。范围：在现有原型架构内增加三类活动板块、首页入口及相应后台配置。原会员、积分、钱包、优惠券、核销和POS对接边界沿用原方案。本文金额、时间、名额和权益为待审批示例；网页原型只模拟操作，不产生真实支付、分享、邀请或退款。

## 1. 三个板块分别解决什么问题

| 板块 | 主要作用 | 更适合的商品 | 顾客最先看清的内容 |
|---|---|---|---|
| 邻里拼团 | 老客邀请邻居一起买，形成可追踪的首购和自提 | 鸡蛋、定量果包、标准蔬菜包等规格明确的商品 | 几人成团、每份规格、拼团价、还差几人、剩余时间、提货门店与时间、失败退款 |
| 限时秒杀 | 在真实活动时段集中成交，带动到店和复购 | 有明确活动配额的高频商品、门店当日计划周转商品 | 开抢/结束时间、到手价、每人限购、可售状态、自提条件 |
| 本周上新 | 让顾客知道门店新增加了什么，形成反复逛首页的理由 | 新引进商品、季节新品、首次上架的产地好物 | 上新日期、商品规格、产地/供应商、价格、库存、适用门店 |

借鉴参考商城“优惠、进度、时间、主操作清楚”的表达。拼团不使用虚构用户、自动补人、虚假销量或反复重置的倒计时；不要求顾客无限邀请或充值后才可参与。

首期先选一家样板店、少量标准件商品，跑通订单、退款、自提和复购后再扩大。称重后补差的商品后置，避免成团后价格和库存口径不清。

## 2. 页面与原架构衔接

首页在直播专区之后、常规商品流之前增加“邻里拼团 / 限时秒杀 / 本周上新”入口与精选商品位；可按活动开关和排序配置，不改四项底部导航。

| 新增页面/区域 | 必要组件 | 主要操作 |
|---|---|---|
| 活动中心 | 三类活动切换、当前门店、活动说明、商品卡 | 进入拼团、秒杀、上新 |
| 拼团列表与详情 | 单买价（如有）、拼团价、规格、成团人数、提货说明、退款规则 | 发起团 / 参加有效团 / 查看我的团 |
| 我的团与进度 | 本人订单、已付款人数、剩余名额、截止时间、状态 | 查看进度、主动分享、查看商品和售后 |
| 秒杀会场与详情 | 场次切换、服务器时间倒计时、活动库存状态、限购 | 到点购买 / 查看预告 / 查看下一场 |
| 上新列表与详情 | 日期分组、分类、规格、适用门店、现售/预售状态 | 查看详情、购买、已授权的到货提醒 |
| 活动订单 | 类型标识、支付/成团/履约/退款状态 | 从活动进入原订单与提货码能力 |
| 后台活动配置 | 类型、门店、SKU、价格、库存、时间、限购、预算、发布 | 草稿、预览、校验、发布、暂停、复制、结束、回滚 |

活动订单沿用原商城订单、支付与资产账本，只增加来源和活动状态字段；不另造一套钱包、积分或核销系统。未成团订单不得生成可核销的提货资格。

## 3. M01 邻里拼团

### 3.1 首期建议规则

- 默认2人成团，每个名额对应一名不同的有效会员。成团人数和参与门槛由后台配置，首期不叠加复杂团长返现或多级奖励。
- 同一团限定同一门店、同一活动、同一SKU与规格；不能把不同门店的库存和自提时间混在一个团内。
- 页面同时写明活动有效期、单团有效时长、当场提货截止条件；团截止时间取这些约束中最早者，不能让顾客支付后才知道已经无法按时提货。
- 每人限参与数量、每场限购和活动总配额均可配置。示例为每人每场1份；同一会员开团后不得再次占用本团第二个名额。
- 只有有效支付成功的订单计入成团人数。点击分享、打开详情、发起待付款订单或模拟头像均不增加人数。
- 原型中的“模拟另一位会员参团”必须明确标为演示控件；不能显示为真实陌生顾客已经付款。
- 邀请为顾客主动操作，正式小程序使用平台支持的分享入口；网页原型不宣称已发送给微信好友或社群。

### 3.2 状态与库存

| 状态 | 顾客看到 | 系统动作 |
|---|---|---|
| 待付款 | 金额、支付时限和门店 | 下单校验活动与资格，短时预占待付库存；未付不增加已付款人数 |
| 拼团中 | “已付款1人，还差1人”、固定截止时间 | 支付回调校验成功后锁定名额与库存，等待成团 |
| 已成团 | 成团成功、可提货时间 | 原子确认满足人数；转入原商城待备货/待自提流程 |
| 未成团已超时 | 成团失败、退款处理中/退款成功 | 关闭继续参团；按每笔支付订单发起原路退款，不自动转单买 |
| 取消/退款中 | 本人订单状态和退款去向 | 排除待退款名额的成团资格；库存按确认的回退节点处理 |
| 已退款 | 退款金额、渠道、时间 | 支付/资产/库存回退只处理一次，保留失败重试和对账记录 |

库存至少区分“可售、待付预占、已付款锁定、已履约、可回售/不可回售”。订单创建预占用于防超卖；支付成功才成为已付款团名额。待付超时释放预占，不把“提交订单”当作“参团成功”。

支付、退款与成团在服务端处理，不能由浏览器按钮直接修改真实状态。最后一个名额被两人同时抢占时，只允许一个订单成功取得名额；不能以客户端显示剩余人数作为扣款依据。

### 3.3 超时、退团与售后

- 超时未成团，对所有需要退还的已付款订单原路退回；金额和退款去向逐单可查。现金退原支付渠道，储值本金与赠金按原出资拆分回退；赠金不变成可提现现金。
- 支付回调晚于成团截止、活动已关闭或名额已失效时，进入可追踪的异常退款流程，不强行把用户塞入另一个团。
- 成团前某订单提出有效退款后，不再计入有效成团人数；不能在退款处理中仍用该名额凑齐人数。库存回售须与退款状态、商品可售性协调，不能一边履约一边回售。
- 团发起者退团不直接删除其他人的支付订单。团可按已发布规则继续等待，或由系统一致地结束并逐单退款；规则必须在购买前说明，不能临时更改。
- 成团后按原商城售后处理。某一笔售后退款不把整团历史改成“未成团”，也不向其他已正常购买的成员追收差价。
- 取消、超时、退款均不可重复退钱、返券、加库存或回退积分。退款失败显示实际状态并可重试，不显示虚假的“已到账”。

## 4. M02 限时秒杀

### 4.1 会场与购买规则

- 每场有明确的开始、结束时间及适用门店；“即将开抢 / 抢购中 / 已售罄 / 已结束 / 已暂停”分别显示。
- 倒计时基于服务器时间与固定截止时间。顾客刷新页面、切换手机时间或重新进入，不得重置活动时长。
- 每个活动SKU配置独立活动库存配额，并受门店真实可售库存约束。活动配额不能大于可用商品库存。
- 示例可设置每人每场1份；提交订单、支付回调都重新校验会员资格、限购、场次、库存和活动版本。
- 未开始时不能提前支付秒杀价；已结束、售罄、暂停时禁用购买并给出原因。不能点了低价按钮，结算时静默切换为更高的日常价。
- 下单短时锁库存，超时未付释放。支付成功锁定购买数量，退款和取消按商品可回售状态决定是否恢复配额。
- 秒杀支付等待时页面显示“处理中”，同一请求重试返回同一订单；不要靠前端多次扣库存防止连点。

### 4.2 生鲜专项

- 商品卡写清“元/份、元/袋、元/盒”等计价单位和重量/数量，不仅展示低价数字。
- 临期商品明确标注临期及到期日，不能包装成普通新品。缺货或品质异常应暂停售卖并处理已付款订单。
- 门店要能备货并在承诺时间自提；履约班次不足时宁可减少名额，不让活动配额脱离分拣能力。
- “已售”“还剩”只使用真实订单与库存口径。无可靠数据时展示“限量供应/售罄”，不补造销量、抢购人数或稀缺提示。

## 5. M03 本周上新

- 新品身份依据当前门店首次正式上架日期，可保留原始商品ID与首次上架时间；改名、换图、重复下架上架不得重置成新品。
- 推荐默认展示最近7天上新的商品，窗口可配置。超过窗口自动退出上新集合，商品仍可继续在普通商城销售。
- “新品”“今日到货”“补货到店”分开：老商品新到货可以展示到货消息，但不能因此变成新品。
- 商品按门店、品类、上新日期筛选；只有当前门店可售或可预售的商品才进入对应列表。
- 必填名称、规格/计价单位、主图、价格、产地/供应商、储存方式、保质期/建议食用时间、库存和上新时间。预售商品另写预计可提货时间。
- 新品可按日常价格销售，不强制打折。若有新品首发优惠，需关联明确活动规则、期限与预算，不能只打“新品价”标签而无真实价格条件。
- 新品也可以关联拼团或秒杀，但“新品”只是展示标签；同一订单只采用一种主活动价，不把多个活动价叠加计算。

## 6. M04 价格与权益优先级

首期采用容易解释、容易对账的规则，后续新增叠加组合必须单独配置并评审。

| 价格/权益 | 首期处理方式 |
|---|---|
| 拼团价、秒杀价 | 两种主活动价互斥；订单锁定一种活动及其规则版本 |
| 会员价 | 与该活动价不再叠折；页面明确“活动价不叠会员商品折扣” |
| 商品券、店铺券、积分抵现 | 活动商品默认不叠加；允许的专项券需白名单配置并单独测预算 |
| 积分换购 | 沿用原兑换商品和现金规则，不自动并入拼团或秒杀 |
| 钱包支付 | 是否可用及本金/赠金扣减顺序沿用原钱包规则；不改变账本性质 |
| 订单运费/配送权益 | 沿用已审批的门店和订单条件；商品活动页不能擅自许诺免配送费 |
| 新品展示标签 | 不改变价格优先级；有首发优惠时须关联对应活动价 |

结算展示商品原价/参考价（有真实依据才显示）、活动优惠、可用/不可用券原因、实付和履约费用。价格变化需要顾客重新确认，不能默默取消优惠或自动加价。

## 7. M05 会员、积分、退款与核销复用

- 常购会员：近90天净商品有效消费≥300元且完成≥3单；优享会员：≥800元且≥8单。原门槛和滚动统计不改。
- 拼团成功、秒杀购买都不是“支付即升等级”。只有原商城达到已完成口径后，现金/储值本金支付的有效商品净款才计入成长；未成团、待付款、退款商品、运费、券及赠金不计入。
- 消费积分默认每满100元有效商品消费积1分（后台可配），逐单向下取整且订单间不累计零头。邀请好友、分享次数、开团次数、充值金额默认都不送消费积分或成长值。
- 如果未来确需邀请奖励，作为独立活动奖励规则、独立预算和流水；不能冒充真实商品消费或永久等级。
- 部分退款按原有效净额和完成单口径反算；全退移除对应有效消费和完成单，并撤回原已发积分。不得重复反向处理。
- 成团并具备提货资格的订单，沿用原提货码、门店和员工核销权限。会员身份码不等于提货码，更不等于已付款证明。
- POS仍与商城独立。活动在指定门店自提，不代表门店收银自动识别拼团价、秒杀价、券、积分或余额。

## 8. M06 后台配置与发布

| 配置组 | 必要字段/能力 |
|---|---|
| 公共信息 | 活动ID、类型、标题、封面、说明、门店ID集合、开始/结束时间、展示排序、上下架开关 |
| 商品与价格 | SKU、规格、活动价、参考价来源、价格版本、适用会员、叠加策略、商品状态 |
| 库存与限购 | 活动库存配额、门店库存来源、单会员/单场/全活动限购、待付款锁定时长、库存释放规则 |
| 拼团专用 | 成团人数、单团有效时长、参团资格、有效支付人数、提货批次、未成团退款规则 |
| 秒杀专用 | 场次ID、服务器时区、开抢/结束时间、场次配额、暂停原因、重复请求幂等键 |
| 上新专用 | 门店首次上架时间、上新展示期限、到货批次、现售/预售、预计提货时间、分类 |
| 履约与售后 | 提货门店、时间窗、核销权限、缺货处理、售后说明、退款状态与异常队列 |
| 预算与成本 | 商品单位成本、包材、履约分摊、支付费用、单位补贴、总补贴上限、最低单位贡献门槛 |
| 来源与分析 | campaign_id、group_id、session_id、channel_id、store_id、分享来源与落地记录、订单关联 |
| 版本与审计 | 草稿版本、预览、审批/发布记录、操作人、变更原因、生效时间、回滚版本 |

发布前校验：时间先后正确、SKU可售、门店有效、库存足够、规格与提货条件完整、价格不为负、预算与成本已填写、退款策略已配置。未通过则只能保存草稿。

活动发布后，订单保留购买时的价格与规则快照。暂停/下架只阻止新增购买，不删除已经支付的订单或已承诺的成团与退款处理。配置调整对新订单生效，不追改历史订单。

后台需有“复制为新活动”功能，复用文案、商品和规则；复制后重新确认日期、库存、价格和预算，不能带着旧时间直接上线。活动报名/成团人数不可通过运营手工填数字伪造。

## 9. M07 毛利与预算护栏

每个活动上线前先补齐实际进货成本和履约成本，不根据示例售价判断是否赚钱。

运营测算建议：单位贡献＝商品净实收（现金+储值本金，不含券、赠金和退款）－商品成本－包材－履约变动成本－支付费用－尚未在净实收中扣除的补贴。已从净实收扣除的优惠不能再扣一次。

- 按SKU、门店和场次核算，避免一个便宜引流品无限放量。
- 设置活动最大售卖量、总补贴上限和最低单位贡献。需要亏损引流时，明确可承受的亏损预算与审批人。
- 预算占用、实际消耗、退款释放分开记录；退款后是否恢复活动名额和补贴额度由活动规则决定，不能重复释放。
- 财务、采购/门店、运营共同确认成本、配额和履约窗口。原型展示的示例金额不代表已经核准活动价。

## 10. M08 私域活动怎么持续用

| 场景 | 运营动作 | 顾客承接 | 复盘重点 |
|---|---|---|---|
| 新品到店 | 拍实物、补齐规格和上架日期，在群内介绍 | 本周上新→详情→购买 | 新品详情转化、实际销量、退货原因 |
| 周末邻里拼团 | 选少量标准件，让老客主动分享同店团 | 拼团进度→成团→自提 | 有效开团/成团、真实首购、退款、30天复购 |
| 固定时段秒杀 | 配好真实时段和配额，提前预告 | 秒杀会场→购买→自提 | 支付转化、售罄时间、单位贡献、连带购买 |
| 直播中介绍活动 | 直播场次关联相同活动商品 | 本场商品→对应活动详情 | 直播来源完成订单与净实收 |
| 活动后复购 | 在顾客授权范围内按偏好推荐常规商品 | 会员日/商城日常购买 | 活动顾客30天复购、复购订单贡献 |

开始时每周固定上新、少量拼团、有限秒杀即可。活动次数、SKU数和预算由样板店的备货/核销能力决定，不承诺固定增长比例。

## 11. M09 统计口径

- 记录模块曝光、详情访问、开团、有效支付参团、成团、付款、完成、自提核销、退款和复购，人数与订单数分开。
- 开团数不等于成交；有效成团率＝成功成团数÷已结束且曾产生有效支付的团数。进行中团单独显示，不混入已结束分母。

## 12. M10 开发验收案例

1. 首页三个入口分别进入对应活动，返回路径和原四底栏可用；无已发布活动时显示正常空状态或隐藏精选位。

4. 未付款订单不计已付款人数；短时预占到期后库存释放一次。

9. 成团后才可按提货窗口生成有效提货资格；待成团码不可被员工核销。
10. 秒杀未开始/暂停/售罄/已结束时不能以旧页面继续购买；切手机时间不能改变正式活动状态。
11. 秒杀订单重复提交返回同一订单；库存不为负，限购不被刷新或多端绕过。
12. 已发布活动价、限购及不可叠加原因在详情和结算一致；优惠失效不静默加价。
13. 新品列表按当前门店首次上架时间生成；老商品改名/重上架不会重置新品日期。
14. 上新期结束后退出上新列表，普通商城仍可购买；预售/售罄状态和提货时间准确。
15. 活动商品已完成后按原规则计成长与积分；待成团、充值、邀请和分享不自动增加。
16. 全退/部分退款按原账本反算并保持幂等；本金、赠金、券和积分不混成一笔现金。
17. 成本、预算、库存或退款配置缺失时不能正式发布；复制活动必须重新校验日期与额度。
18. 暂停活动不删除历史订单；购买时价格/规则版本可查，发布与回滚有操作记录。
19. 活动完成订单与退款、库存、支付、资产账本可对账，异常退款能跟进并重试。
20. 手机390/430宽及电脑预览可读可点，无横向溢出；演示控件和真实用户操作区分清楚。
