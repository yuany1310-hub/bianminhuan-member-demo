# 便民欢每日签到｜开发评估清单

版本：2026 年 10 月 27 日｜原商城升级方案增补

## 一、这次要开发什么

在现有小程序和运营后台中增加签到功能，让顾客每天有回来的理由，让运营以后可以自己配置签到活动，不必每次改代码。

顾客端先展示「今日签到、签到日历、连续／累计进度、3 天奖励、7 天奖励、月度奖励、我的奖励」。后台可以设置门槛、奖品、积分数量、有效期、库存和预算。

**送什么、送多少尚未确定。默认全部显示“奖励待设置”，不预设积分数，不承诺赠券或实物，也不产生真实待发奖义务。** 原型中的签到、领奖与后台保存均用于评估页面和开发范围；不代表真实活动已经发布。

原会员等级、消费积分、充值、拼团、秒杀、上新与门店核销规则保持原口径。签到另建营销活动记录，不把签到天数当成消费金额或购买订单。

## 二、顾客页面布局（C01—C06）

| 编号 | 页面区域 | 需要显示与操作 |
| --- | --- | --- |
| C01 | 入口 | 首页、会员中心、活动中心可进入「每日签到」；入口可由后台开关及排序。 |
| C02 | 今日签到 | 今日日期、已签到／未签到、签到按钮、当前规则摘要；点击后明确反馈，重复点击仍只记一次。 |
| C03 | 签到进度 | 当前连续天数、本周期累计天数、最近签到日期；按当前活动口径展示达标进度。 |
| C04 | 日历 | 已签到、今天、未签到与未来日期；未来日期不可点击签到；断签／补签状态按规则展示。 |
| C05 | 阶段奖励 | 3 天、7 天、月度三个初始布局位；门槛、名称、奖励内容由后台配置，可增删或停用。 |
| C06 | 我的奖励 | 查看领取状态、积分流水、优惠券去向、实物领取订单、领取有效期与适用门店。 |

奖励卡不得只有一个“领取”按钮。至少区分以下状态：

| 状态 | 顾客看到什么 | 能否领取 |
| --- | --- | --- |
| 奖励待设置 | 规则／奖品尚未配置，展示“奖励待设置” | 否，不用空配置发放 0 分冒充奖励 |
| 未达标 | 当前进度与还差几天 | 否 |
| 可领取 | 奖励内容、领取截止时间 | 是，提交时重新校验资格、库存与预算 |
| 领取中 | 正在处理，防止重复提交 | 暂不能重复提交 |
| 已领取 | 领取时间及查看入口 | 否；可查看原记录 |
| 领取失败 | 原因、是否可重试；保留原资格 | 按失败原因允许重试，不重复扣库存或发积分 |
| 已过期 | 领取期限已过 | 否 |
| 已领完／缺货 | 本奖励暂不可领取及后续处理方式 | 否；不能直接标记为“已领取” |

## 三、签到和周期口径（C07）

### 每天怎么记

- 默认由顾客主动点击「签到」，**打开小程序不等于已经签到**。若以后需要自动签到，应作为独立规则和报价项确认。
- 正式系统使用服务端北京时间（Asia/Shanghai）划分自然日，每天 00:00 换日；不以手机时间判断资格。
- 同一会员、同一签到活动、同一自然日只生成一条有效签到记录。重复点击、重试、并发请求不能重复记天数或发奖。
- 未登录时先完成正常会员身份确认；不以多个页面访问次数增加签到天数。

### 连续和累计不能混用

| 口径 | 定义 | 断签怎么处理 |
| --- | --- | --- |
| 连续签到 N 天 | 自最近一次连续签到开始，按相邻自然日累计；3 天、7 天可以按此配置。 | 默认漏一天后连续进度重新开始，既有签到历史仍保留。 |
| 本周期累计 N 天 | 在活动配置的周期内累计有效签到日，同一天不重复计数。 | 漏签不清空已累计天数，周期结束后按规则重置。 |

「连续天数」和「本周期累计天数」可同时展示，但奖励卡必须标清使用哪一个计数。

### “1 个月”先保留选择，不写死成同一概念

后台要能明确选择并让开发分别评估：

1. **连续 30 天**：固定 30 个连续自然日，与日历月份无关。
2. **自然月累计 N 天**：每月 1 日至月末统计，2 月、闰年和 28／29／30／31 天需正确处理，门槛不得超过该月可签到天数。
3. 若要「自然月全勤」，必须单独确认：是否要求该月每天签到、月中加入者如何处理、何时可以领；不能把它默认为“累计 30 天”。

原型可用「30 天阶段奖励／月度奖励」作为布局名，旁边注明口径待确认。正式活动发布前必须选定具体口径。

### 断签、补签和重复活动

- 默认不开补签，断签重算连续天数；历史累计记录不删除。
- 如开放补签，需要明确可补日期范围、次数、是否扣积分、补签是否计入连续奖励、领取后的回溯处理，单独估工。
- 每个奖励门槛必须绑定「活动版本 + 统计周期 + 奖励档位」。同一会员在同一周期同一档位最多领一次。
- 一次性活动、按自然月重复或达标后重新开一轮，是不同周期策略。首期至少明确配置的活动起止周期；无限循环、跨月自动续期不得默认开启。

## 四、奖励配置与到账（C08—C10）

| 奖励类型 | 后台配置 | 顾客领取后 |
| --- | --- | --- |
| 待设置／不启用 | 保留布局位，不启用发奖 | 不发积分、不发券、不生成实物订单 |
| 积分 | 每日／阶段积分数、到账方式、有效期、发放总量及预算上限 | 写入「签到奖励」营销积分流水，账户余额与流水一致 |
| 优惠券 | 关联已有券模板、张数、有效期、适用商品／门店、总量与每人限额 | 发放到“我的优惠券”，保留签到活动来源 |
| 实物／换购资格 | 奖品 SKU、规格、门店、可用库存、领取时限、自提规则；有补差价时需明确金额 | 生成可追踪的奖品领取／兑换订单，到店凭该订单核销 |

每日奖励可关闭，阶段奖励可分别启停。每日奖励与 3／7／月度奖励能否同日同时领取，需要后台明确设置，不能由前端自行决定。

**营销积分与消费成长分开：**签到获得积分可以进入原积分账户及积分商城，但来源是营销活动；签到、领奖、获券和免费实物领取本身不增加消费金额、会员消费订单数或消费等级。若实物采用补差价换购，只有符合原口径且履约完成的实际商品款按原规则处理，不能重复计算。

**领奖必须能重试，不能重复发奖：**签到记录、奖励资格、发奖记录分别留存。先校验资格，再处理预算／库存和发奖，失败时按状态恢复或继续处理；同一领取请求和回调只能生效一次。不能仅把页面按钮改成“已领取”就视为发奖成功。

**规则快照：**奖励资格或领取单形成时保留活动版本、门槛、奖品、数量、有效期与适用门店的快照，领奖时使用该快照核验。修改后台配置不追溯改写已发奖励。新规则从何时、哪个周期生效应明确；未配置期间的签到是否补发奖励需运营另行确认，默认不承诺自动补发。

## 五、后台需要哪些设置（C11）

| 配置组 | 字段／功能 |
| --- | --- |
| 活动基础 | 名称、活动编号、开始／结束时间、展示文案、入口开关、排序、适用门店、参与客群 |
| 统计规则 | 每日主动签到；连续／周期累计；换日时区；周期策略；月度口径；中断处理；补签开关及限额 |
| 每日奖励 | 是否启用、奖励类型、积分数／券模板／奖品、到账／领取方式 |
| 阶段奖励 | 门槛天数、名称、奖励类型和数量、同日叠加策略、每周期领取次数、领取期限 |
| 资金与库存 | 积分发放总量、券总量、实物分门店库存、单人限额、总预算、预算耗尽和缺货时的处理 |
| 会员与履约 | 关联会员 ID、适用身份／等级、积分有效期、实物提货时段及核销权限；POS 独立边界保留 |
| 发布管理 | 保存草稿、预览、校验、审批／发布、暂停／结束、规则版本、操作日志；已发布规则按生效时间调整 |
| 数据与异常 | 签到人数、有效签到天数、连续／累计分布、各档达标人数、领取人数、失败／缺货／过期、积分与奖品消耗、后续购买与复购 |

校验至少包括：门槛为正整数；奖励数与库存／总量为合法值；积分类型未填写积分数不能发布；券／实物未关联有效模板或 SKU 不能发布；开始结束和领取期限有效；自然月门槛合法；总预算／总量和单人上限不冲突。允许保存未完成的草稿，但未通过配置校验不得发布为真实奖励活动。

后台保存与正式发布需要清楚区分。本原型可保存本机配置并应用到“演示预览”，不能显示为真实活动已上线。

## 六、开发报价怎么拆（C12）

请开发按以下工作包填写「是否复用、改造点、工作量、费用、依赖、交付时间」，**具体费用由开发报价，本清单不编金额**。

| 工作包 | 最小一期建议 | 可另行报价的扩展 |
| --- | --- | --- |
| 顾客页面 | 入口、签到按钮、日历、进度、3／7／月度奖励位、奖励记录与状态 | 动效包装、更多入口样式、独立活动专题 |
| 签到服务 | 会员识别、服务端按日唯一、连续／累计计算、周期与断签处理 | 自动签到、补签、复杂循环、跨活动历史迁移 |
| 奖励服务 | 奖励待设置；可配积分；资格校验、手动领取、积分流水、失败重试与幂等 | 优惠券发放、实物库存与领取订单、混合奖励、补差价 |
| 后台配置 | 规则、门槛、积分数、有效期、限额、预算、草稿／预览／发布、版本和日志 | 多门店差异化、多客群分层、审批层级与更复杂的月度全勤 |
| 数据与运营 | 签到、达标、领奖、积分消耗及异常记录导出 | 多渠道归因、自动触达、复购分析、实验对比 |
| 联调与测试 | 既有会员／积分／活动接口，日切和并发，旧功能回归，权限和故障处理 | POS 互通、新支付链路、第三方营销平台；均不混入默认签到报价 |

若已有积分、优惠券、商品库存和员工核销能力，开发须先实测复用范围，再报价。奖励形式暂未确定时，建议分别报「签到＋积分基础版」和「优惠券／实物扩展版」，不把未选功能全部打包为一个不透明报价。

## 七、验收清单（C13）

1. 未配置奖励时，3 天、7 天和月度奖励位可见且标“待设置”，不会擅自发固定积分或承诺奖品。
2. 打开小程序不自动记签到；主动点击后当天有清楚反馈，再点不重复记天数。
3. 改手机时间不能提前签到；北京时间 23:59／00:00 换日正确，同日并发仅一条有效记录。
4. 连续 3 天和 7 天按实际相邻自然日计算，漏签后连续计数按默认规则重算，历史记录保留。
5. 周期累计不因漏签丢失历史，同一自然日只累计一次；周期结束后按配置正确切换。
6. 连续 30 天与自然月口径区分；2 月、闰年、月末和月中加入等边界按选定规则验收。
7. 默认补签入口关闭；若报价包含补签，次数、范围、积分扣费及是否计入连续奖励与配置一致。
8. 未达标不能领；已达标且奖品有效时可领取；重复点击或重复回调最多发放一次。
9. 积分领取后余额、营销积分流水、活动来源和有效期一致，不增加消费成长、消费订单数或消费等级。
10. 后台修改奖励档位或积分数后，演示预览按所选草稿显示；真实系统必须通过发布校验才生效，已发奖励不被改写。
11. 领奖失败、库存不足、预算耗尽、领取过期均有正确状态；失败不能假显示成功，安全重试不重复扣减。
12. 如包含券，发到正确会员的券账户，模板、数量、门店、有效期和适用范围正确。
13. 如包含实物，领取订单关联正确 SKU 和门店，库存不超卖，提货码仅核销一次；免费领取不记消费成长。
14. 活动结束／暂停／规则换版后，签到入口、既得资格与领取期限处理符合已发布规则快照，日志可追溯。
15. 首页、会员中心和活动页入口在手机宽度下可用；原会员、钱包、积分商城、拼团、秒杀、上新与订单流程通过必要回归。

## 八、开发前需确认，当前不替运营拍板

- 每日签到是否送奖励；3 天、7 天和月度各送什么、送多少。
- 用连续签到还是周期累计；“1 个月”具体是连续 30 天、自然月累计还是月度全勤。
- 是否补签、是否循环、每日和阶段奖励是否叠加、每期最多可领几次。
- 奖励领取时限、积分有效期、适用门店与客群、预算和库存、缺货后如何处理。

以上暂不确定不妨碍先评估功能和页面工作量，但正式发布真实活动前必须配置并审批。


## 用户最终确认的积分使用期限

消费积分、签到营销赠分及其他营销积分统一按**到账自然年**管理：当年12月31日23:59:59到期，次年清零可用正积分。领取资格有效期与积分使用期限分开；券按券模板、实物按自提期限处理。积分退回沿用原年度批次，过期不恢复成新年度积分；钱包本金、赠金、消费成长和历史流水不随积分清零。正式服务需批次台账、定时清零与访问兜底、跨年冻结/退款冲正验收。


## 2026-10-27 最终消费积分口径

- 默认每单每满100元有效商品消费积1分，后台可配置；按满额档数向下取整，订单间不累计零头。
- 36.80元普通订单、6.90元拼团、3.90元换购现金部分均积0分，消费成长仍按有效商品金额和完成单数记账。
- 充值不计消费积分；签到独立营销赠分，具体奖励未定，默认待设置。
- 下单存比例快照和规则版本，完成按快照发放；退款按原单已发积分冲回，部分退款只冲回原比例差额；跨年已过期部分不重复扣回或恢复。
- 所有积分在到账自然年12月31日23:59:59到期，次年清零可用正积分；流水保留，钱包和会员成长不清零。
- 旧300分+3.90元鸡蛋兑换仅为流程占位，需与100:1比例、赠分预算及成本重新配套审批，不能作为正式权益。
